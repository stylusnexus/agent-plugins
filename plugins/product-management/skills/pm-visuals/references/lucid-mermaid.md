# Lucid preferred; Mermaid fallback

## Route by user intent
Prefer an available Lucid connector for editable product diagrams. Lucidspark suits workshop boards; Lucidchart suits structured diagrams, subject to the live connector's capabilities. Choose the available tool that fits the requested collaboration; no connector is bundled.

Discover the host's live tools and read the complete applicable descriptions before every operation. Connector names, authentication and supported shapes can change; do not assume that the other host has the same integrations. The suite packages instructions and source files, not credentials or a Lucid connection.

1. Read the relevant PM analysis, existing document when editing, and requested source. Keep evidence IDs and unknowns visible. An instruction to build tool capabilities is not itself an instruction to create a cloud document.
2. If Mermaid already exists, preserve it verbatim for the Lucid Mermaid conversion tool; use dedicated sequence/ERD tools when the live instructions require them. Do not re-author it as Standard Import JSON. Existing SVG should use the supported SVG conversion path when available, following live tool prerequisites.
3. If a custom board needs a structured specification, read `lucid://skills/diagram-specification` through the connector's resource tool before constructing it, every time required by the tool. Never guess shape classes or JSON. Validate with the connector's validation tool; resolve structural errors and relevant layout findings. Check truncated/skipped checks. Use assisted layout only when compatible with the desired board arrangement.
4. Create or update only the requested document. Preserve unrelated content; return the actual document link/ID from the tool. Do not create sharing links, change access, invite people or post comments unless authorized. Existing permission to create a requested diagram need not be re-confirmed.
5. Read back/export and inspect the result when possible: section count, labels, note placement, clipping, relationships, source/evidence labels. A successful tool return is not a visual-quality check. Save local diagram source/data and link metadata with the project so the analysis remains portable; a cloud URL alone is not a portable artifact.
6. If the connector is absent or fails, say so and deliver `.mmd`/Mermaid plus the evidence table. Mermaid is not a collaborative sticky-note application and cannot promise the exact six-panel spatial layout. Use offline HTML/SVG when precise board layout is useful. State whether Mermaid was rendered or only supplied as source. Do not install an integration or bypass authentication without appropriate authorization.

## PESTLE workshop board
Use a two-row arrangement when useful: Political / Economic / Social on the first row; Technological / Legal / Environmental on the second. PESTLE and PESTEL cover the same categories. Make six large labelled containers with discrete editable notes and an optional dot-voting legend. Adapt note counts to actual content; do not invent findings to fill the board.

Each substantive note has an ID, one external signal, evidence status and a short implication. Keep source/date, geography, horizon, exposure mechanism, uncertainty and proposed response in a companion table keyed by ID. Blank placeholders must say they are prompts, not findings.

Facilitate: establish scope → collect independently where feasible → clarify and deduplicate → distinguish evidence from assumptions → discuss implications → optionally vote on what deserves investigation → select actions/owners/review triggers. Explain one category at a time for a novice and draft examples from the real project. Voting records participant priorities, not probability, impact, customer validation or consensus; never manufacture participants or votes. Keep minority concerns visible. Use native voting only if the connector actually supports it; otherwise label manual counts clearly.

## Connector availability

Discover available connector tools and confirm access in the current session. This plugin does not install or authenticate a connector. Cloud creation and rendering require separate verification.
