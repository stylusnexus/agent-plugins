# Platform rules: fetch first, every time

This file is a protocol, not a rulebook — the actual rules must be fetched fresh at use time. Nothing below should be treated as a current, reliable statement of any platform's policy; platform rules and moderation norms drift, sometimes quickly.

## Why this matters more than it looks like it should
Community and self-promotion rules are usually set at the level of the individual community, not the whole platform: a subreddit's own sidebar or wiki, a Discord server's own rules channel, a forum's own posting guidelines. A platform-wide summary — including this file — is never a substitute for that. A platform's site-wide content policy is one layer; each individual community's stricter or looser house rules sit on top of it and are what actually gets enforced day to day.

## The protocol
1. Before drafting anything for a specific community, fetch that community's current rules page directly.
2. Record the exact URL and the date fetched in the [participation log](../templates/community-participation-log.md).
3. If a rule can't be fetched (blocked, login-walled, no written rule exists), say so explicitly and default to the most conservative reading: participate as a genuine member for a while before any promotional post, and never cross-post the same pitch to multiple communities at once — identical cross-posted pitches are a commonly cited pattern moderators flag as spam, but confirm against each community's own rules rather than treating this as universal.
4. Re-fetch before reusing a community for a new campaign, even if it was checked recently — rules change, and moderation teams change with them.

## A few durable patterns (still verify, but these drift less)
These are this suite's own working observations about common community norms, not a cited rule from any one platform — verify each against the specific community's current, posted rules before relying on it:
- Launch-showcase and maker-showcase communities commonly expect something people can actually try (not a landing page or sign-up wall alone), a short, specific, no-hype description, and the maker present in the thread actually answering questions rather than just dropping a link.
