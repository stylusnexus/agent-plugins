stylusnexus / agent-plugins

Skills for agents that have to ship something.

agent-plugins is an open-source (MIT) plugin marketplace from Stylus Nexus: ten plugins and 62 skills that install natively into Claude Code and OpenAI Codex, and into about seventy other coding agents through the Skills CLI. Eight are skill packs for building, shipping, deciding what to build, and getting it noticed; two are tools.

Tool plugins

Two plugins ship executable code rather than markdown, so they live in their own repositories and install from there.

work-plan

CLI + viewer

Track-aware daily planning over GitHub issues: shared tracks, AI clustering, coverage, and dependency-aware next-up. Pure-stdlib Python CLI plus an accessible VS Code viewer with a repo-qualified dependency graph.

defect-scan

15 languages

Language-aware defect hunter. Detects the stack, triages files by risk, runs the real analyzers (ruff, mypy, tsc, eslint, rubocop, brakeman), then reports findings in confidence tiers, correlated against existing issues.

Installing

Add the marketplace once, then take whichever packs you want. Plugins run code on your machine, so review a plugin's source before installing it.

Claude Code

Install in Claude Code

Terminal, VS Code, and JetBrains extensions share one config, so one install covers all three.

/plugin marketplace add stylusnexus/agent-plugins
/plugin install ship-pipeline@stylus-nexus

Skills carry the pack name: /ship-pipeline:prove-it. To get updates automatically, open /plugin → Marketplaces → stylus-nexus → Enable auto-update.

Codex

Install in Codex

CLI, app, and IDE extension. Codex reads its own index, so the same marketplace works unchanged.

codex plugin marketplace add stylusnexus/agent-plugins
codex plugin add ship-pipeline@stylus-nexus

Type $ship-pipeline:prove-it or run /skills. In the ChatGPT app, type @. To update, run codex plugin marketplace upgrade stylus-nexus, then the add command again.

These packs have opinions.

They're repo-agnostic: every skill detects your conventions rather than assuming them, and defers to a repo-local version of itself when your project defines one. They still hold a point of view: evidence before "done", detect rather than assume, one rule per owner. Each README states the opinion plainly, so you can tell quickly whether it fits how you work.

Questions

How do I install agent-plugins in Claude Code?

Run /plugin marketplace add stylusnexus/agent-plugins, then /plugin install ship-pipeline@stylus-nexus for each pack you want. Skills then carry the pack name, as in /ship-pipeline:prove-it.

How do I install agent-plugins in Codex?

Run codex plugin marketplace add stylusnexus/agent-plugins, then codex plugin add ship-pipeline@stylus-nexus for each pack you want. Invoke a skill with $ship-pipeline:prove-it, or run /skills.

How do I install agent-plugins in Cursor, Copilot, or another agent?

Run npx skills add stylusnexus/agent-plugins. The Skills CLI detects which agents you have and writes the skills into each one; add --skill and skill names to take only some.

How do I keep agent-plugins up to date?

In Claude Code, enable auto-update for the stylus-nexus marketplace under /plugin, Marketplaces. In Codex, run codex plugin marketplace upgrade stylus-nexus, then add each pack again. With the Skills CLI, run npx skills update.

What is ship-pipeline?

ship-pipeline is the agent-plugins skill pack for the daily loop: it reads the issue, grounds assumptions in the live database, proves the change works, then reviews, merges, and promotes it, for one issue or a batch.

Why is a skill called /prove-it in one agent and /ship-pipeline:prove-it in another?

Claude Code and Codex plugins prefix skills with the pack name. Skills installed through the Skills CLI or npm have no prefix.
